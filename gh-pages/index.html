wolfram-agents-runtime

An external, multi-provider, observable runtime for Wolfram's LLM family (LLMGraph · LLMGraphSubmit · LLMSynthesize · LLMPrompt · …) — without a Wolfram license or Wolfram Cloud. One agent-facing CLI; LLMGraph is one capability, not the whole thing.

no Wolfram license 6 LLM backends no API key needed (claude-cli / Qwen) live web monitor 139 offline tests green 
# a natural-language task → planned graph → result
wolfram_agents do "summarize the pros & cons of X and recommend one"
# or: one-shot · orchestrated graphs · env self-check
wolfram_agents synthesize "what has atomic number 2?"
wolfram_agents graph run examples/renga.json -i Topic=spring
wolfram_agents doctor --fix     # tells you exactly what's configured / how to finish

What it does — and what it doesn't (yet)

✅ Solves today

  • LLMGraph model with zero Wolfram dependency — auto deps + concurrency on plain Python/CI
  • Natural-language task → graph → result — wolfram_agents do "…" has an LLM plan the task into an LLMGraph, then runs it (self-repairing, LLM nodes only)
  • Tasks persist as portable graphs — do saves the planned LLMGraph to .json + a real Wolfram .wls you can open & run in Mathematica (kernel-verified round-trip)
  • Swappable execution engine — same semantics on a zero-dep reference executor or LangGraph; LangGraph is detachable, proven equal by tests
  • No vendor lock-in, no Anthropic key — 6 backends, per-node mix, auto; free via claude-cli / Qwen
  • LLM + Python + Wolfram-compute + conditional nodes — one graph, with failure propagation
  • One-shot (LLMSynthesize) + async events (LLMGraphSubmit → Task)
  • See inside the pipeline — live monitor, 2-layer DAG, per-node status / timing / tokens / cost
  • Migrate & verify — WL spec → IR, exact dual-engine parity on deterministic nodes
  • Agent-friendly setup — doctor --json --fix + setup.sh / setup.ps1 (Windows), offline-tolerant

❌ Doesn't do (yet)

  • Not a production agent framework — no tool-calling (LLMTool), no loops/state-machines, no checkpoint/memory
  • Not 100% Wolfram-compute migration — heavy symbolic stays in Wolfram; {"wolfram":…} needs wolframscript
  • LLMConfiguration tools / SystemCredential auth — not wired (WL-specific)
  • Information returns dicts — not Wolfram Dataset/Graph objects
  • Streaming stable on claude-cli only — LangChain-backend streaming pending
  • LLMGraphSubmit — full-graph eval then slice; one run at a time per graph
  • Research / self-hosted runtime — not a turnkey product

Two packages: wolfram_llmgraph (the LLMGraph library) and wolfram_agents (the umbrella entry). Each family member is its own module — mirroring Wolfram's one-page-per-function family.
